# 日程渠道通知开发计划

日期：2026-09-25。状态：首版代码、本地验证及质量复核完成，尚未发布或部署。

## 目标与范围

微信为主要通知渠道。后台从已配置的微信、Telegram、Discord 输入渠道中选择一个或多个明确的接收目标。所有输入渠道成功保存的日程都进入统一提醒流程，不按来源筛选。不新增邮件或企业微信接入。

沿用日程提醒提前量；取消提醒、日程改期及成功删除同步更新任务。支持日、周、月重复与时区。失败的日历写入不触发提醒；重试成功后纳入。以本助手的成功操作为日程状态依据，外部日历客户端的直接改动尚不自动同步。

## 实施步骤

- [x] 建立独立日程投影、接收目标与持久化投递表；成功操作同步，清理历史日志不影响后续提醒。
- [x] 微信按 Bot 账号和接收用户加密保存最新上下文令牌；主动发送时读取最新令牌。接入 Telegram、Discord 普通发送接口。
- [x] 加入后台通知开关、已有会话选择、测试发送和投递状态；新安装/升级默认关闭，用户选定收件目标后启用。
- [x] 由应用生命周期管理调度任务，支持原子领取、限次重试、过期处理和重启恢复。对发送结果不确定的请求标记待核对，不盲目重发。
- [x] 本地回归跨渠道输入、微信令牌刷新/恢复、日程变更、并发去重、连接故障与重试、周期及时区、权限与后台页面；记录实测范围和剩余限制。
- [x] 经用户明确授权，完成 TypeSafe 辅助核验及本地复查，修复并发登记问题。
- [ ] 发布部署、选择真实接收会话并验证实际送达。

## 设计决定

1. SQLite 保存状态和任务，无需额外消息队列。后台每 30 秒检查一次，提醒不是秒级保证。
2. 成功记录按稳定 event_id 投影；老记录以 CalDAV UID 或记录 ID 回退。启动时补入尚存历史成功记录的当前状态；只调度启用后到期的提醒，不补发旧提醒。已经清理的历史无法自动恢复。
3. 一个目标属于一个 Bot 账号和会话。微信 token 加密存储，账号凭据变更后必须重新收到消息才能建立新账号的目标。后台不显示 token。
4. 任务按日程、重复实例、提前量和接收目标去重。提醒配置变更取消旧目标待发任务；日程变更取消旧版本待发任务。正在网络发送中的消息不能撤回，平台缺少幂等保证时不承诺 exactly-once。
5. 停机后仅允许 5 分钟内到期的任务补发，并且日程尚未结束；更旧任务标记过期。临时连接失败或限流最多尝试 3 次，超时等不确定结果要求人工核对。
6. 微信长期静默后的可达性为上线后观察项，不作为本地开发完成的前置条件；即时发送、持久化恢复和失败状态必须验证。

## 发布与回滚

先完成代码和本地验证；生产启用时明确接收目标并检查真实到达。升级前备份 SQLite 和配置。关闭通知开关即可停止领取新任务；新增表保留，旧版本可忽略，回滚不删除数据。发布镜像、生产部署及真实测试消息分别记录结果，不将模拟测试当成生产验收。
